# Stage 23 — Career

You have the work. This stage is about making it legible: a portfolio that reads in sixty seconds, a resume with measurable outcomes, interview answers with numbers in them, and a public trail that makes recruiters come to you.

It is the shortest stage and the one people skip, which is why strong engineers get overlooked by weaker ones who packaged better.

**Time:** 2-4 weeks, alongside applying · **You need first:** [Stage 22 — Real Projects](../22-real-projects/README.md) · **You leave with:** a portfolio, a resume, three project stories and a target list

## What you will be able to do

- Structure a GitHub profile so a reviewer understands you in under a minute
- Write resume bullets that state an outcome and a measurement
- Answer Python, SQL and LLM-fundamentals questions with confident, short answers
- Work through a system-design interview using a repeatable framework
- Tell a project story as context → constraint → decision → measurement → lesson
- Contribute to open source without wasting a maintainer's time
- Write a technical article that gets read
- Build in public on a cadence you can sustain
- Run a job search with targeting, referrals and a take-home strategy

## The shipping project

There is no code project here. The deliverable is a package: a pinned GitHub profile with three repositories whose READMEs lead with a measurement, a one-page resume, three rehearsed project stories, and a target list of twenty companies with a route into each.

## How to know you are done

- A stranger can tell what you build from your GitHub profile in under a minute
- Every resume bullet has a number or a concrete outcome in it
- You can give a five-minute version and a thirty-second version of each project
- You can answer "why not just fine-tune" without hesitating
- You have a target list with a named route into at least half of them
- You have shipped something publicly in the last month
